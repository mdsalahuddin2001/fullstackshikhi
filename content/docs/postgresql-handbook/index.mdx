## Your mission

Build the database skills to answer three questions confidently: **Is this data correct? Why is this query slow? What happens when two requests arrive together?**

This handbook expands the eight stages in your [shared PostgreSQL roadmap](https://chatgpt.com/share/6ad63062-4574-83ec-bae7-dc7bd10760e1). It assumes basic JavaScript and terminal familiarity, but no SQL experience. Examples use English and a familiar Dhaka shop dataset. The [Bangla foundation lessons](/docs/postgresql) remain available alongside it.

You will work through a school system, an online shop, and a tenant-aware support system. The SQL labs use PostgreSQL 17 or 18; the operational examples specify where environment setup matters. SQL runs in your local PostgreSQL, not inside this page.

## The learning loop

1. **Understand:** read the mental model and trace one example.
2. **Predict:** write down the output before running the query.
3. **Try:** spend 15–30 minutes on a challenge without opening the solution.
4. **Check:** compare rows, constraints, and failure behavior, not just syntax.
5. **Explain:** describe the result aloud, then change one requirement.

A chapter is complete when you can solve its challenge again tomorrow without copying. Checking a box records your self-assessment; it does not grade your SQL.

## What “everything” means here

Every area of the shared roadmap has a place: SQL, modeling, concurrency, indexing, application integration, migrations, security, backups, and scaling. Core topics include executable exercises; advanced operational topics include decision exercises and runbooks. Replication, PITR, and deployment require infrastructure beyond a single local database. This is a developer handbook, not an exhaustive replacement for the PostgreSQL manual.

Use the [reference and coverage map](/docs/postgresql-handbook/reference) to revisit vocabulary and find the relevant official documentation.

## Go deeper after the core path

Add these six practical modules as weeks 13–16, or study them alongside the relevant core chapters. This is an extension of the original 12-week foundation, not extra work squeezed into the same schedule.

| Module | What you will prove |
| --- | --- |
| [Advanced modeling](/docs/postgresql-handbook/advanced-modeling) | Correct time boundaries, currency semantics, and overlapping-booking rejection |
| [Reliable workflows](/docs/postgresql-handbook/reliable-workflows) | Retry-safe operations, outbox recovery, and soft-delete conflicts |
| [Search](/docs/postgresql-handbook/search) | Full-text relevance, typo tolerance, and safe filtering |
| [Bulk data](/docs/postgresql-handbook/bulk-data) | Classified import failures and resumable backfills |
| [Operations debugging](/docs/postgresql-handbook/operations-debugging) | Evidence that separates pool, lock, and query waits |
| [Runnable API project](/docs/postgresql-handbook/api-project) | A working API, real integration tests, and local deployment |

The API project is available as a [downloadable source bundle](/labs/postgresql/reservation-api.zip). Its single-actor identity model and local container settings are deliberately scoped for learning; the chapter explains the remaining deployment responsibilities.
